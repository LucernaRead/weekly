## 5. Freeze-baseline guard conflict (UNRESOLVED — needs the coordinator's decision)

`tools/freeze.py` was modified at **2026-11-11 12:00** (uncommitted working-tree change; `git log` for the file shows only commit `8df40906 Move weekly production toolkit into the repo`) to add a "Runtime guard (2026-11-11)": `main()` asserts Pillow major == 13 and aborts (exit 2) otherwise, printing `runtime: <exe> | Pillow <v> | FreeType <v>` in every run. The guard's docstring says: "the canonical stack is tools/venv (Pillow 13.0.0, pinned in tools/requirements.txt). W47 pt-ko froze 0/8 because its shipped SVGs were built by system python3 (Pillow 10.2.0 / FreeType 2.13.2), whose whole-string measurement differs from the venv stack by ~+1.11px per Korean-space boundary."

This directly contradicts the task brief and core KIT fix #15 (build + freeze under /usr/bin/python3 PIL 10.2.0; venv PIL 13 flips freeze 0/8). The guard's diagnosis of the MECHANISM is correct (dual-stack drift), but its prescription (force freeze to the venv) is incompatible with the family's build stack. **Empirically confirmed 2026-11-11:** freeze baseline run under the venv on a system-python3-built edition gives **0/8** (ja: `ja/freeze-ja-venv.log`; zh-tw: `zh-tw/freeze-zh-tw-venv.log`, rc=1; build-copies deleted after each run). The 8 editions built before 12:00 (en/de/es/fr/it/pt/nl/ru) froze **8/8** under /usr/bin/python3. The pt-ko 0/8 the guard cites was freeze(venv) vs build(sys) — the same mismatch, not evidence that the venv is the right build stack.

**Decision taken (recorded, not a unilateral fix):** do NOT bypass the guard (e.g. by running a de-guarded copy — that would hide a deliberate tool change and violate "do not touch tools/"), do NOT rebuild ja/zh-tw under the venv (contradicts the task brief's explicit interpreter lock and would make them the only venv-built editions with different text layout), and do NOT report the venv 0/8 as an edition failure (the editions are fine; the gate is broken by the tool change). **Freeze baseline is BLOCKED for ja and zh-tw until the coordinator resolves which stack is canonical** — either revert the guard, or move the family's build stack to the venv (a whole-family rebuild). The freeze DIFF still runs under the venv (it is a pure text comparison; the Pillow version cannot affect its result) and was used for the ja (2901) and zh-tw (822) adjudications. Both editions' records and KITs state the block prominently, with the evidence logs; `gen-record.py` in ko3 was parameterized (`freeze_baseline` / `gates_note` fields) so the ja/zh-tw records do not falsely claim 8/8.
