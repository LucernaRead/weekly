## §1 建造方法

1. 開工前置核查：`files/weekly-report-w45-en-zh-tw/` 與 `hidden_files/weekly-report-w45-en-zh-tw-build/` 均不存在、無同名進行中進程——無重複派工，正常開工。開工時先以 `tools/freeze.py baseline` 驗證核心 8/8 SVG 逐字節復現（見 §6），後才動工。
2. 複製 W45 英語核心 build → 本建造目錄；五個 content 模塊的 OUT 全部改道 `files/weekly-report-w45-en-zh-tw/svg`（expanduser 形式，首跑前打印核對）。
3. 變換：`transform.py`（建造目錄根，自含可復現；生成器見 `scratch/gen_full.py`，映射表見 `scratch/pairs.py`）——phase 0 結構編輯（bridge→expl、P1 徽章、svglib TC、P8 顯式印刷集）＋ phase 1 全量計數斷言（229 鍵、398 處，任一不符即中止不寫）＋ phase 2 最長優先替換 ＋ phase 3 殘留／禁詞斷言。計數全部命中。變換按 tools/README 第 17／18 條：不用 AST 字節偏移、f-string 片段用裸文本替換；整數計數以原始文本為準。
4. 單進程 driver 重渲染（README 第 7 條）：一個 Python 進程依次 import content12、content34、content56、content7、content8；構建警告（FLOW OVERFLOW／HEAD TOO WIDE）= 0；練習總量 150（見 §6）。
5. 渲染：CairoSVG 卡片 1950×2700 ×8；印刷 PDF（svg2pdf + pypdf 合併）；網頁 PDF（1400 寬 JPEG q85）。
6. 解釋器：driver 與 render.py 一律用 `tools/venv/bin/python`（Python 3.12.3、PIL 13.0.0、cairosvg 2.9.1）；系統 python3 無 cairosvg（實測 ImportError），不得用於渲染。本建造目錄無獨立 run.py 文件——單進程 import 命令即 driver（作用等同 run.py），解釋器與 PIL 版本與 render.py 相同，皆為上述 venv。
7. 修復輪規則執行：FIX1（見 §7）只寫進 transform.py，隨後全新重拷核心 build、重跑 transform.py、整期重渲染；重渲染後逐頁哈希比對：僅 P7 變化，其餘 7 頁與首輪逐字節同，P8 不變（符合預期：FIX1 的兩條注文不在 P8 印刷集內）。
