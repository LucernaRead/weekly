### P8 answer-note style (paren vs dash)

CORRECTED in the 2026-10-28 fix round (proof B2). The pre-fix KIT text
here claimed the shipped W43 vol1 core and W43 fr P8 SVGs both print
dash style — that claim was FALSE for the W43 FR SVG. Verified from the
shipped W43 zh-cn×fr P8 SVG (paren 150/150) and its build code
(`content8.py:119,121`, `f"{e_['n']}. {e_['key']} ({e_['note']})"` and
`f"{e_['n']}. ✓ ({e_['note']})"`): the family's shipped fan-out code
governs the bracket form (tools README #14), and the W43 FR fan-out's
deliberate dash→paren change is the same-pairing precedent. This
edition now follows it: `content8.py` builds keys as
`f"{e_['n']}. {e_['key']} ({e_['note']})"` and writing items as
`f"{e_['n']}. ✓ ({e_['note']})"`. The W45 core's dash code is NOT
followed here. Follow-on (same round): the 34 distinct P8 notes that
cited CJK words were converted to pinyin-only citations, because
svglib's `_fw()` converts a parenthesised pair containing CJK to
full-width parens — and freeze --strict-cjk counts those as added CJK
(the core P8 carries only 11 full-width parens, all in test stems, so
~39 converted key pairs would have failed the gate). Post-fix
measurement: keys-area half-width parens 150/150, full-width parens 0,
strict-CJK added chars 0.
