## SOP §1.1 migration note (this edition vs the W46 old style)

The W46 core code was copied as the template, then migrated to the SOP §1.1 visual spec, using the W43 `2026-w43-en-zh-tw` build as the reference implementation (same svglib.py/bslib4.py, adapted only for this pairing and VOL.4):

- Paper #fbfaf6 (was W46 warm ivory #f7f1e2); no gold anywhere (GOLD/BRICK/DARK all removed); double-line outer frame removed; no near-black background (teaser strip is book-green #37402f with #f4efe1 text).
- CJK body in Noto Serif CJK TC (per-character font fallback in svglib.py: Newsreader for Latin → Noto Serif CJK TC → DejaVu Sans; sans: Noto Sans CJK TC → DejaVu Sans); Latin body/titles in Newsreader; masthead in UnifrakturMaguntia.
- Structural headings, bands, footer and page lines use full-width spaces (　), never 「·」. 「·」 survives only inside inline enumerations (multiple-choice options, gloss word lists, the P6 timeline legend, foreign-person names such as 戴安娜·克瑞兒) — the same rule the W43 reference demonstrates.
- Chinese numbers unspaced: `第1版／共8版`, `11月22日`. Side boxes are borderless with light ground #f0eee5. Charts use olive #46581f (was brick/gold).
- P1 masthead reworked to the W43 pattern (top strip, edition line, badge line, single olive rule with the three-colour Lucerna moth sitting on it). Headline 96px → 60px (45pt). Article titles 34→32px; section heads 28/26→25px; P7 column heads 24→25px.
- Error clinic: wrong sentences no longer brick-red — plain ink with an `✗ ` prefix (as in W43).
- **Punctuation:** the new svglib has no ASCII→full-width conversion (the old `_fw` is gone), so 569 ASCII punctuation marks in CJK strings were converted to full-width in the source (， ？ ！ ： ； （ ）) by a tokenize-based script (`scratch-zh-tw/punct_apply.py`), with guards: thousands separators (`1,200元`) untouched, times (`14:00`) untouched, English sentences containing CJK words untouched. Verified by dry run before applying; all files re-compiled; rebuild re-gated (see below).
- **Known SOP §1.1 gaps (shared with the approved W43 reference build):**
  - **Drop cap:** §1.1 asks for an olive drop cap (~4 lines) on the headline's first paragraph. No W43 page implements one, and the layout code has no drop-cap support; implementing it by hand would be a custom ragged-margin hack with occlusion risk. Not implemented; recorded here.
  - **P8 exercise stems:** §1.1 step 3 says P8 stems go to 15.4pt (20.5px, "W46 current value"), but the W46 zh-tw core used 13.8px (= 10.35pt) for all 38 P8 items, and this edition keeps 13.8px — 38 exercises + writing strip + 150 keys cannot fit the 8-page budget at 20.5px stems. The **answer keys** do meet the §1.1 floor: measured **9.75pt** on both PDFs (see below). Build 13 tried raising the stems to 20.5px: 8 FLOW OVERFLOW, 381 occlusion flags, ~700px short of the 8-page budget — rolled back by ruling to 13.8px (content8.py 37 × f.ex size=13.8, diff vs Build 12 backup empty; second-round independent proofread measured stems 10.35pt, keys 9.75pt, render clean).
  - **D7 size ladder (Build 13 trial, kept in Build 14):** Notes boxes 20.5→18px (= 13.5pt, ladder top); P7 three-column body 21.5→22px, P7 exercises 20.5→22px, P4 exercises 21.5→22px (= 16.5pt, ladder bottom); article body 24px (= 18pt) and sidebar body/exercise stems 22.5px (= 16.875pt) were already in range and untouched. Second-round independent proofread verified zero overflow, 0 occlusion flags, hierarchy still clear.
- The `lucerna-moth.svg` asset was copied from the W43 reference dir into `assets/` (the moth is the Lucerna brand mark; `assets/lucerna-moth.svg`, 1,324 bytes).
