## Adjudications and shortfalls (for the independent proofreader)

- **SOP §1.1 restyle (this issue's defining change).** The first build
  used the W46 old style (warm ivory `#f7f1e2`, gold, double frame,
  near-black base, 「·」 furniture, old margins). A coordinator
  correction (2026-11-10) judged the Italian and Japanese cores not
  final for the same reason and ordered a §1.1 self-check before
  reporting. This core was fully restyled to §1.1 and re-rendered:
  paper `#fbfaf6`, no gold/brick/dark/near-black anywhere (0 occurrences
  in the final SVGs), no double frame, margins top 54pt / sides 66pt /
  bottom 48pt, badges A2 `#5c6e30` / B1 `#46581f` / B2 `#37402f`, CJK
  body in Noto Serif CJK SC, furniture in full-width space. The engine
  is the W47 DE core's `bslib4.py`/`svglib.py`, adapted for zh-cn (SC
  glyphs, “Notes｜” gloss prefix kept from the W46 zh-cn-en precedent).
  Verified item by item against SOP §1.1 in the self-check below.
- **P8 stems 17.5px = 13.12pt, below the SOP ladder.** The SOP ladder's
  step-3 floor for P8 stems is 15.4pt and the DE reference core uses
  18.5px (13.9pt); this core uses 17.5px (measured 13.12pt, 296 spans).
  This was needed to fit the brief-required P8 image (210px writing
  photo + 1-line caption) together with all 150 keys on one page at the
  §1.1 geometry: at 18.5px the test flow ended too low and the image
  crossed the keys rule; at 17.5px the test flow ends col 3 y = 965,
  the image ends at 1270.6, the keys rule sits at 1320 and the keys flow
  ends at 2491 (bottom 2560). Recorded as an adjudication, not hidden.
  The P8 answer keys themselves measure **9.98pt** (361 spans in the
  keys region), above the SOP's 9.75pt floor — see “Measured totals”
  in the proofread record.
- **P8 geometry.** Test flow ends col 3 y = 964.8; image ends 1270.6;
  keys rule (hline) at y = 1320, keys title at 1358, keys flow top
  1384, keys end col 3 y = 2491.1 (bottom 2560). The canonical
  occlusion audit reports no flag there, and the builder visually
  checked the final P8 card: clean.

### Fix — Round 1 verdict R2 (P7 “waitfor” lost space; 2026-11-10)

- **Defect:** the P7 A2-column para rendered as “waitfor a parcel” —
  the space between “wait” and “for” was genuinely lost (verified in
  the SVG: a single `<text>` element ‘waitfor a parcel, ask first, then
  go to the’). Source `content7.py:27` has “wait for”.
- **Root cause (reproduced with `wrap()` directly):** at 21.5px the
  greedy pass correctly wraps line 2 as ‘」 (Has my parcel arrived?)
  When you wait’ and line 3 as ‘for a parcel…’. Then the kinsoku START
  pass (oidashi) pulls “吗” down because line 2 starts with “」”
  (NO_START), making line 2 over-wide; the seam repair then sheds the
  trailing Latin word “wait” glyph by glyph to the head of line 3 via
  `_kinsoku_join_piece`, which only restores the space when the piece
  ends with ASCII punctuation (.,:;!?) — “wait” ends with “t”, so no
  space is restored → “waitfor”. At 20px the same text wraps
  correctly (different breaks). A full-SVG scan for merged Latin words
  found only this one instance in the whole issue.
- **Fix:** a post-pass at the end of `wrap()` in **this core's copy**
  of `svglib.py` only (never touch core-de's copy), applied after the
  word-integrity repair and before `return lines`, which restores lost
  internal spaces using the input as ground truth: if the space-stripped
  lines reproduce the stripped input, each line is aligned to its span
  in the input (via the positions of non-space characters) and replaced
  with its exact input slice (boundary spaces excluded, since lines are
  rstripped by construction). A restored space widens a line by at most
  one space, inside the SEAM_SLACK (28px) the seam repair already
  allows. Rationale for a post-pass rather than patching
  `_kinsoku_join_piece`: inserting a space in the join is unsafe in the
  oidashi-fragment case (a word split by oidashi, then seam-re-shed,
  would get a wrong space inside the word, and the word-integrity repair
  would then corrupt it further); the input-slice restoration can only
  make lines more faithful to the source.
- **Verification:** the 21.5px reproduction now returns ‘wait for a
  parcel, ask first, then go to the’; a full-SVG merged-word scan on
  the final render is 0; the SVG-text diff vs the pre-fix render is
  exactly the badge line and the ‘waitfor’ → ‘wait for’ line.
- **Status after this fix:** re-gated clean (occlusion 0, p8 150/150,
  freeze 8/8); Round 2 self-proofread zero-issue. No push, no insert,
  no Discord post, no chat dump.
